How the course works

Class time is for seeing models work, asking why they work, and practicing the reasoning needed to build and debug them.

1

See the demo

Each unit starts with a compact working example in PyTorch: data, model, loss, training loop, and observable behavior.

2

Unpack the ideas

We then trace tensor shapes, objectives, gradients, architectural choices, and failure modes using equations and diagrams.

3

Build and explain

Students extend the demo, use outside resources to fill gaps, and learn to explain what the code is doing—not merely run it.

AI coding is part of the course

Students are expected to learn an AI coding workflow using tools such as Claude Code or Codex. These tools may help scaffold, test, and debug project code, but students must verify the output and be able to explain every submitted component. No paid AI account is required.

Prerequisites

  • Calculus: derivatives, chain rule, and gradients, including matrix inputs
  • Linear algebra: vectors, matrices, norms, and the basic idea of SVD
  • Probability: conditional probability and Bayes' rule
  • Python: reading, writing, and debugging small programs

What to bring

  • A laptop for regular class demos and coding activities
  • A paper notebook for derivations, diagrams, and review
  • Curiosity and a willingness to inspect model failures

No previous deep learning course is assumed.

Learning outcomes

By the end of the course, students should be able to:

  1. Translate a learning problem into data, parameters, a model, a loss, and an evaluation plan.
  2. Trace forward and backward computation through linear models, MLPs, CNNs, RNNs, and transformers.
  3. Read and debug a compact PyTorch training pipeline, including tensor shapes and optimization behavior.
  4. Explain self-attention, causal language modeling, and the core structure of a GPT-style model.
  5. Compare VAE and GAN objectives, strengths, failure modes, and appropriate uses.
  6. Design, implement, evaluate, and clearly present an individual deep learning project.

Essential policies

The shortest version: use tools honestly, own your work, and ask for help early.

AI use and integrity

AI coding tools are permitted and expected for learning and project development. Disclose material use, verify all output, and never submit work you cannot explain. AI tools are prohibited during the final exam. Rutgers academic integrity standards apply.

Attendance and preparation

The course is face-to-face and class meetings include demos and practice that are difficult to reproduce from slides alone. Attend prepared to code, take notes, ask questions, and participate.

Access and accommodations

Students seeking disability-related accommodations should contact the Rutgers Office of Disability Services and share the approved letter with the instructor as early as possible.
